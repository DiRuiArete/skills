# 体验设计流 — 产出：五层次定调 + 体验地图 + 峰终设计 + 激励与命名

## 输入
先查 plan 文件「已确认事实」：已有机会画布/用户画像则以其为设计输入。

## 完成度锚点（本流 1-10）
1 体验没框架 · 3 战略存在层定调 · 5 五层次自查完 · 7 体验地图+服务蓝图成 · 9 峰终+激励设计完 · 10 全案可交付

## Step 1：你的体验问题（3 选项决策点）
```
✅ 进入体验设计流。完成度：1/10

【你的问题 — 3 选项】

★ A. 产品做了很多但用户感受不到好
   完整度：9/10 · 产出：五层次自查 + 峰终重设计
   理由：多半是资源撒匀了——没有峰值的体验等于没有体验。

  B. 用户旅程有断点/流失点找不到
   完整度：8/10 · 产出：体验地图 + 服务蓝图
   理由：把旅程画出来，断点自己会浮现。

  C. 留存差，想加激励体系
   完整度：7/10 · 产出：上瘾回路设计
   理由：能做，但先确认基础体验闭环，否则激励是给漏桶加水。

→ 我的推荐：A
回 A/B/C。
```

## Step 2：战略存在层定调
```
✅ 完成度：1/10 → 3/10
先回答最里层的两个问题（一次一个）：
1. 你要通过这个产品成为什么样的存在？
2. 用户为什么需要你持续存在？
答不清楚，外面四层做得再漂亮都是空转。
```
五层次读 references/five-layers.md「框架」；由内向外的评估法读其「怎么用」。

```
  C. 先优化感知层（视觉/交互）（4/10 ⚠️）——最外层的抛光救不了里层的缺失
→ 我的推荐：A
回 A/B/C。
```

## Step 4：体验地图 + 峰终设计（3 选项决策点）
```
✅ 完成度：5/10 → 7/10
以你的第一只羊为主角画体验地图（触点序列 + 情绪曲线），然后做资源分配决策：

【资源怎么分 — 3 选项】

★ A. 集中做尖峰值 + 守住终值，其余允许平庸
   完整度：9/10
   理由：记忆由峰值和终值决定——资源有限时这是唯一理性分法。

  B. 全旅程平均提升
   完整度：4/10  ⚠️
   为什么低：处处 70 分 = 用户记不住任何东西。

  C. 只修流失最大的断点
   完整度：7/10
   理由：止血优先可以，但止完血还是要回来设计峰终。

→ 我的推荐：A
回 A/B/C。
```
地图与服务蓝图画法读 references/experience-map.md「框架」「怎么用」。

## Step 5：激励与命名
```
✅ 完成度：7/10 → 9/10
两个可选强化件：
1. 激励系统：给高频动作装上瘾回路（触发→行动→奖励→投入）——读 references/addiction.md「怎么用」
2. 命名检查：名字是文化资产，自带场景与情绪——对照 references/naming.md「Checklist」
```
