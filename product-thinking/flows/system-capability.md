# 系统能力诊断流 — 产出：确定性核检 + 效率杠杆 + 迭代规划 + 关键任务

## 输入
先查 plan 文件「已确认事实」：已有产品/体验方案则以其为诊断对象。

## 完成度锚点（本流 1-10）
1 没诊断过 · 3 确定性核检完 · 5 效率杠杆找到 · 7 迭代规划成 · 9 关键任务锁定 · 10 系统能力方案闭环

## Step 1：你的系统问题（3 选项决策点）
```
✅ 进入系统能力诊断流。完成度：1/10
产品的本质是向用户交付确定性——确定性建立依赖，崩坏摧毁信任。

【你的问题 — 3 选项】

★ A. 用户用了但不依赖/复购差
   完整度：9/10 · 产出：确定性核检清单
   理由：不依赖 = 确定性没交付到位，这是系统问题不是营销问题。

  B. 成本高/跑不快，被同行压着打
   完整度：8/10 · 产出：效率杠杆分析
   理由：效率是系统的核心竞争杠杆。

  C. 迭代混乱，每版都像重新开始
   完整度：8/10 · 产出：迭代主线规划
   理由：迭代没有主线 = 团队在原地画圈。

→ 我的推荐：按痛点选
回 A/B/C。
```

## Step 2：确定性核检
```
✅ 完成度：1/10 → 3/10
逐项核检（一次一项）：
1. 用户来找你，最怕落空的那件事是什么？
2. 这件事你现在能做到几成兑现？靠人肉还是靠系统？
3. 哪个环节最常掉链子？
```
核检方法读 references/certainty-efficiency.md「框架」「怎么用」。

## Step 3：效率杠杆（3 选项决策点）
```
✅ 完成度：3/10 → 5/10

【你的效率杠杆在哪层 — 3 选项】
★ A. 组织层（人效/协作方式）9/10——最难抄袭的效率
  B. 渠道/供应链层 8/10——结构性成本优势
  C. 工具层（自动化/AI）7/10——见效快但同行也买得到
→ 我的推荐：从 A 里找一个别人抄不走的
回 A/B/C。
```

## Step 4：迭代规划（3 选项决策点）
```
✅ 完成度：5/10 → 7/10
第一版（或下一版）做什么？

【取舍 — 3 选项】
★ A. 只做最核心的确定性交付点，其余全砍（9/10）——先站住，再长出来
  B. 核心 + 1-2 个差异化点（7/10）——可以，但每加一个都要过"没有它会死吗"
  C. 尽量做全，怕用户觉得简陋（3/10 ⚠️）——第一版做全 = 每个都做不深
→ 我的推荐：A
回 A/B/C。
```
版本主线读 references/certainty-efficiency.md「怎么用」；对照其「反模式」。

## Step 5：生死线关键任务
```
✅ 完成度：7/10 → 9/10
最后锁定：当前阶段你的**关键任务**是哪一个？（只能有一个）
判断：这件事做不成，其他一切成绩都会归零吗？是 → 它就是关键任务，资源全部向它倾斜。
```
展开读 references/certainty-efficiency.md「框架」。

## 收尾（完成度 ≥9/10）
诊断结论 + 迭代规划 + 关键任务写入 plan 文件「流产出」节。
```
✅ 系统能力完成度：9/10
【下一步 — 3 选项】
★ A. 回体验设计把确定性落到旅程里 9/10 → 继续：体验设计流
  B. 重新校验机会与模式 7/10 → 继续：创新破局流
  C. 输出系统能力方案 8/10
→ 我的推荐：A
```
