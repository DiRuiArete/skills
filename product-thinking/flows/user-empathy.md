# 用户理解流 — 产出：情绪判读 + 真伪需求结论 + 用户画像卡

## 输入
先查 plan 文件「已确认事实」：已有目标用户/调研材料则直接进对应 Step。

## 完成度锚点（本流 1-10）
1 只有模糊人群 · 3 情绪信号判读完 · 5 防御问题排查完 · 7 角色化陷阱自查完 · 9 画像卡成型 · 10 可直接输入产品设计

## Step 1：你想懂用户的什么（3 选项决策点）
```
✅ 进入用户理解流。完成度：1/10

【你的问题 — 3 选项】

★ A. 分不清用户说的是真需求还是客气话
   完整度：9/10 · 产出：情绪判读 + 防御排查
   理由：最常见也最致命——嘴上的需求会说谎，情绪不会。

  B. 想给用户分类，做差异化策略
   完整度：8/10 · 产出：两套画像 + 策略表
   理由：分类清楚才能定服务谁、放弃谁。

  C. 想知道产品该顺着人性哪个部分设计
   完整度：7/10 · 产出：角色化自查 + 自我/自律判断
   理由：偏底层，做完 A/B 再来收益更大。

→ 我的推荐：A
回 A/B/C。
```

## Step 2：情绪四件套判读
```
✅ 完成度：1/10 → 3/10
把你观察到的用户反应发我（用户说了什么/做了什么），我们逐条判读：
愉悦=被满足；不爽=没被满足；愤怒=边界被侵犯；恐惧=痛点所在。
一次判读一条。
```
判读方法读 references/emotions.md「框架」「怎么用」。

## Step 3：防御排查（3 选项决策点）
```
✅ 完成度：3/10 → 5/10
用户在被观察/被访谈时会启动防御——说给你听的是他的角色，不是他自己。

【你的调研方式 — 3 选项】

★ A. 看真实行为数据 / 现场观察
   完整度：9/10
   理由：行为不说谎。防御只污染语言，不污染动作。

  B. 场景化提问（问"上次你怎么做的"，不问"你要什么"）
   完整度：8/10
   理由：把用户带回具体场景，绕过意识层防御。

  C. 直接问卷问需求
   完整度：3/10  ⚠️
   为什么低：问出来的是角色化的标准答案。

→ 我的推荐：A + B 组合
回 A/B/C。
```
防御机制读 references/emotions.md「框架」；反模式对照其「反模式」。

## Step 4：角色化陷阱自查
```
✅ 完成度：5/10 → 7/10
自查一个问题：你的产品是给**个体**用的，还是给**角色**用的？
- 给个体（生活场景）→ 必须顺应真实人性，不能按"应该"设计
- 给角色（工作/协作场景）→ 可以按角色预期设计
```
展开读 references/roles.md「框架」「怎么用」。

## Step 5：用户分类与画像卡
```
✅ 完成度：7/10 → 9/10
两套画像各过一遍：
1. 羊群系：第一只羊是谁？头羊是谁？狼是谁？
2. 三态系：你的用户里大明/笨笨/小闲各占多少？主服务哪类？
```
策略差异读 references/personas.md「框架」；按 templates/user-persona-card.md 填画像卡。

## 收尾（完成度 ≥9/10）
画像卡 + 真伪需求结论写入 plan 文件「流产出」节。
```
✅ 用户理解完成度：9/10
【下一步 — 3 选项】
★ A. 把用户洞察转成体验设计 9/10 → 继续：体验设计流
  B. 回头修正机会判断 7/10 → 继续：机会判断流
  C. 输出用户研究报告 8/10
→ 我的推荐：A
```
