# 产品标准流 — 产出：安全感劝退点清单 + 价值感闭环 + 向往感画面 + NPS 设计

## 输入
先查 plan 文件「已确认事实」：已有定位/品牌输出则以其人群与价值主张为标准的锚点。

## 完成度锚点（本流 1-10）
1 没想过 · 4 劝退点列出 · 6 安全感解法成型 · 8 价值感闭环 + 向往感设计 · 9 加 NPS 系统 · 10 全闭环

## Step 1：开场 + 先攻哪一维（3 选项决策点）
输出：
```
✅ 进入产品标准流。
三维度：安全感（防守）+ 价值感（竞争）+ 向往感（口碑）。
顺序：先除劝退点，再做竞争力，最后做加分项。

【先攻哪一维 — 3 选项】

★ A. 安全感（防守 — 致命劝退点）
   完整度：9/10 · 产出：5+ 个用户劝退点 + 每个的解法
   理由：木桶最短板。再多亮点也救不了被劝退的用户。

  B. 价值感（竞争 — 同价位体验闭环）
   完整度：7/10 · 产出：完整体验场景 + 必要功能闭环
   理由：防守做完了再做竞争。已清楚劝退点可直接攻这一维。

  C. 向往感（口碑 — 用户向往画面嫁接）
   完整度：6/10 · 产出：3+ 个唤起向往的小功能
   理由：基础有了再做加分。

→ 我的推荐：A
回 A/B/C。
```

## Step 2：攻安全感
```
✅ 完成度：1/10 → 4/10
先看致命缺点，再看亮点。

请你列出 3-5 个用户的潜在"劝退点"——
（物理风险 / 数据安全 / 信任问题 / 体验崩塌 / 隐私失控 都算）
```
等用户列出后：
```
✅ 完成度：4/10 → 6/10（劝退点清单出炉）

针对每个劝退点，用"突破行业惯性"法——
切换到用户视角问："他知道这些约束吗？他在乎吗？"

【你下一步 — 3 选项】

★ A. 逐个劝退点找突破方案
   完整度：9/10
   做法：每个劝退点用"行业惯性 vs 用户视角"分析找解法
   理由：行业觉得合理、用户不接受的妥协点，就是安全感的提升空间。

  B. 先看竞品怎么处理这些劝退点
   完整度：7/10 · 做法：原子级对标
   理由：知己知彼，但容易陷入"跟竞品比"而不是"为用户解"。

  C. 直接进价值感维度
   完整度：4/10  ⚠️
   为什么低：劝退没解，做亮点白费。

→ 我的推荐：A
回 A/B/C。
```
视角切换法展开读 references/product-standard.md「维度 1：安全感（底线）」。

## Step 3：价值感 / 向往感（3 选项决策点）
完成安全感后：
```
✅ 完成度：6/10 → 8/10（安全感设计完）

【下一维 — 3 选项】

★ A. 价值感（同价位的完整体验闭环）
   完整度：9/10
   做法：不堆功能，做闭环。砍掉"东拼西凑"的半截功能。
   理由：抄功能不抄场景闭环 = 东施效颦，对用户毫无价值。

  B. 向往感（用户向往画面嫁接）
   完整度：8/10
   做法：找用户向往场景（露营/客厅/咖啡馆），用小功能嫁接
   理由：便宜的向往感比贵的更高级——它来自洞察，不是来自钱。

  C. 验证现有标准 + 做 NPS
   完整度：7/10 · 做法：建 NPS 系统，赋予功能权重
   理由：标准要落到数据反馈上才是闭环。

→ 我的推荐：A → B → C 顺序做
回 A/B/C。
```
两维方法分别展开读 references/product-standard.md「维度 2：价值感（竞争力）」「维度 3：向往感（口碑）」。
