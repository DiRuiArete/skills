# 体验设计流 — 产出：三筛子判断 + PEA 六维度评审表

## 输入
先查 plan 文件「已确认事实」：已有定位/产品标准则以其为取舍锚点；用户带着具体功能争议来的，直接进 Step 2。

## 完成度锚点（本流 1-10）
1 不知道怎么取舍 · 3 选定具体功能 · 5 跑完 1 筛 · 6 高频通过 · 7 机会通过 · 8 务实通过 · 9 加 PEA 评审 · 10 进开发

## Step 1：开场 + 你卡在哪（3 选项决策点）
输出：
```
✅ 进入体验设计流。
三筛子：高频 × 机会 × 务实。任何功能要进开发，三个 yes 才行。

【你的状态 — 3 选项】

★ A. 团队在为某个具体功能吵 — 帮我做决策
   完整度：9/10 · 产出：3 筛子过完 + 进/不进开发的判断
   理由：最实战的入口。具体功能能直接套三筛子。

  B. 不知道哪些功能算高频
   完整度：7/10 · 产出：判断高频的方法 + 高频功能清单
   理由：基础问题，但大多数人卡的不是这层——是不知道砍什么。

  C. 想做 PEA 评审，给我模板
   完整度：8/10 · 产出：PEA 六维度模板（直接读 templates/pea-template.md）
   理由：模板是实战工具。已有具体功能可以直接套。

→ 我的推荐：A
回 A/B/C。
```

## Step 2：具体功能决策
```
✅ 完成度：1/10 → 3/10
请描述这个功能（一句话即可）：功能名 + 主要动作 + 团队为什么吵。
```
收到后（关键节点——三筛子套用，一次只问一筛）：
```
✅ 完成度：3/10 → 5/10
你的功能：[复述]

【先验证哪一筛 — 3 选项】

★ A. 高频判断（用户每天/每周用得到吗？）
   完整度：9/10
   理由：基础筛——不高频的功能下面两筛都白搭。

  B. 机会判断（竞品做了吗？做透了吗？）
   完整度：7/10
   理由：知道高频后才看机会，直接看机会容易"为差异化而差异化"。

  C. 务实判断（加这个体验有没有带新麻烦？）
   完整度：6/10
   理由：最后一筛。前两筛过了再看务实，否则容易因小失大。

→ 我的推荐：A
回 A/B/C。
```
三筛的判断方法分别展开读 references/experience-pea.md「准则 1：不分大众小众，只看高频」「准则 2：权衡机会——找竞品没做好的地方」「准则 3：务实——不要带来更多麻烦」。

## Step 3：跑完三筛子
每筛用户答完更新完成度：高频过 → 6/10；机会过 → 7/10；务实过 → 8/10。
任何一筛 ≤6/10 给警告：
```
⚠️ [筛子名] 评分 [X]/10 — 命中反模式（大众小众判断 / 抄竞品 / 概念诱惑）

【你的选择 — 3 选项】
★ A. 砍掉这个功能（推荐）9/10——半截功能 = 价值感损失，砍干净比半截好
  B. 改造成另一种实现 7/10——保留底层任务 + 换更务实的解法
  C. 强行做（你的判断我尊重）3/10 ⚠️——可以，但记进失败案例库下次复盘
→ 我的推荐：A 或 B
回 A/B/C。
```

## Step 4：进 PEA 评审（3 选项决策点）
```
✅ 完成度：8/10 → 9/10（三筛子都过了）
现在进 PEA 评审——把功能写成正式方案。

【你的下一步 — 3 选项】
★ A. 我帮你填 PEA 六维度（推荐）9/10——模板逼你想清楚每个维度，避免拍脑袋立项
  B. 直接进开发，不走 PEA 4/10 ⚠️——流程开口子 = 全员跳过
  C. 读 PEA 模板再决定 7/10（读 templates/pea-template.md）
→ 我的推荐：A
```
评审流程展开读 references/experience-pea.md「PEA 流程：把以上准则落地到团队」。填表时**只问问题，让用户自己填每个维度**。

## 收尾（完成度 ≥9/10）
把功能名 + 三筛子结果 + PEA 六维度写入 plan 文件「流产出」节。
```
✅ 体验设计完成度：9/10
【下一步 — 3 选项】
★ A. 进用户研究（验证假设需求）9/10 → 继续：用户研究流
  B. 进技术路线（确定实现方案）8/10 → 继续：技术路线流
  C. 进定价 6/10（一般放最后）→ 继续：定价流
→ 我的推荐：A
```
