# 复盘流 — 产出：复盘会方案 + 问题 To-Do 清单 + 组织智库沉淀

## 输入
先查 plan 文件「已确认事实」：已知上一款产品的结果与 PEA 计划则直接进对照复盘。

## 完成度锚点（本流 1-10）
1 没复盘过 · 4 诊断批判会原因 · 6 五条清单设计完 · 9 To-Do 落地 · 10 智库化

## Step 1：开场 + 你的痛点（3 选项决策点）
输出：
```
✅ 进入复盘流。
复盘的目标 = 把经验变成能力，不是功过赏罚。

【你的痛点 — 3 选项】

★ A. 上次复盘开成了批判会，互相甩锅
   完整度：9/10 · 产出：诊断 + 修复方案（顺序/对照/落地三方面）
   理由：最常见的复盘陷阱。3 个原因清晰，一个一个修。

  B. 想知道怎么开好复盘会，给我清单
   完整度：8/10 · 产出：5 条复盘会硬清单
   理由：方法论入口，但不解决具体卡点。

  C. 复盘完团队没行动，怎么落 To-Do
   完整度：7/10 · 产出：To-Do + 具体人 + 跟进周期机制
   理由：落地问题。但前提是复盘开对了。

→ 我的推荐：A
回 A/B/C。
```

## Step 2：批判会陷阱诊断（3 选项决策点）
```
✅ 完成度：1/10 → 4/10
复盘开成批判会的 3 个原因——

1. **顺序反了** — 先批判 = 团队防御 = 不会暴露真问题
2. **对照错了** — 对结果数据复盘 = 发散无边、错误归因
3. **没落地** — 没有 To-Do + 具体人 = 等于没开

【先修哪个 — 3 选项】

★ A. 修顺序（先肯定再补短板）
   完整度：9/10——顺序对了团队就敢于暴露不足，这是最根因的修。

  B. 修对照（用 PEA 六维度对照计划）
   完整度：8/10——拿出 PEA 计划逐条对照（不是对结果数据），结构化避免发散。

  C. 修落地（每问题落 To-Do + 负责人）
   完整度：7/10——闭环最后一公里，但前提是顺序和对照对了。

→ 我的推荐：A → B → C 顺序修
回 A/B/C。
```
对照法展开读 references/retro.md「关键结构：对照"计划"复盘，不是对照"结果"」。

## Step 3：开复盘会（3 选项决策点）
```
✅ 完成度：4/10 → 6/10
复盘会 5 条硬清单：
1. CEO / 业务一号位必参加（不是"代表参会"）
2. 专门主持人（不参与讨论）
3. 会前所有人预先写下答案
4. 流程严格把控（轮流发言，主持人公开纠正）
5. 按时开，雷打不动嵌入工作流

【你下一步 — 3 选项】
★ A. 设计你下次复盘的具体方案（推荐）9/10——议程 + 主持人指南 + 提前作业题
  B. 给我复盘记录模板 8/10——直接读 templates/retro-template.md
  C. CEO 怎么带头（上交手机/记笔记）7/10——创始人示范原则
→ 我的推荐：A
回 A/B/C。
```
清单展开读 references/retro.md「怎么开好复盘会（清单）」；To-Do 机制读「关键工具：每个问题落到具体 To-Do + 具体人」。

## 收尾（完成度 ≥9/10）
按 references/retro.md「输出物模板」把复盘会方案 + To-Do 清单写入 plan 文件「流产出」节。
```
✅ 复盘完成度：9/10
【下一步 — 3 选项】
★ A. 用复盘结果规划下一代节奏（推荐）9/10 → 继续：节奏流
  B. 把复盘经验固化到流程 8/10 → 继续：流程流
  C. 复盘完做下一款产品 7/10 → 回主菜单选 0→1 阶段
→ 我的推荐：A
```
