# 用户研究流 — 产出：共创会方案 + 场景验证 + 真/假需求标注清单

## 输入
先查 plan 文件「已确认事实」：已有定位（人群边界）则围绕该人群设计调研；没有则先提示走定位流。

## 完成度锚点（本流 1-10）
1 想做调研 · 3 选定方法（共创/现场） · 5 共创会方案设计 · 7 加场景验证设计 · 9 真假需求标注完 · 10 转成 PEA 输入

## Step 1：开场 + 你打算怎么搞（3 选项决策点）
输出：
```
✅ 进入用户研究流。
反直觉原则：少做一对一访谈，多做共创会 + 现场观察。
原因：被访谈的用户会"表演"。

【你的状态 — 3 选项】

★ A. 我打算做 N 个一对一访谈
   完整度：5/10  ⚠️
   做法：让我提醒你为什么不行 + 引导改造
   理由：访谈不是不能做，但有"表演"问题。共创会 + 现场观察是替代方案。

  B. 想做共创会，给我 4 条原则
   完整度：9/10
   产出：共创会方案（分小组/问场景/问感性/不现场出结论）
   理由：最有效的原方法。

  C. 已经收集了一堆需求，想验证哪些是真的
   完整度：8/10 · 产出：场景模拟验证清单
   理由：实战入口。脱离场景争论需求都是耍流氓。

→ 我的推荐：B 或 C（看你状态）
回 A/B/C。
```

## Step 2：共创会设计（3 选项决策点）
```
✅ 完成度：1/10 → 3/10
共创会 4 条原则：
1. 分小组（避免意见领袖）  2. 问场景（不问需求）
3. 问感性期待（不问具体方案）  4. 不现场出结论

【你下一步 — 3 选项】
★ A. 帮我设计具体共创会方案 9/10——完整议程 + 问题清单 + 主持人指南
  B. 给我每条原则的"反例 vs 正例" 8/10——先理解透了再设计
  C. 我有现场观察方案，想结合共创会 7/10——去用户现场/销售一线观察的指南
→ 我的推荐：A
回 A/B/C。
```
原则展开读 references/user-research.md「共创会的 4 条原则」；观察方法读「方法 2：去看，不要去问」。

## Step 3：场景验证（3 选项决策点）
```
✅ 完成度：5/10 → 7/10
共创会收集到的需求只是"假设"。硬约束：回到具体场景验证。

【你的需求验证方式 — 3 选项】

★ A. 真实场景模拟法（推荐）
   完整度：9/10
   做法：每个需求放回 3 个真实场景模拟用户体验
   理由：脱离场景没法判断真假需求。

  B. A/B 测试
   完整度：7/10
   做法：MVP 上线看真实数据
   理由：可以做，但成本高——先用场景模拟筛掉假需求再上 A/B。

  C. 找用户访谈追问
   完整度：5/10  ⚠️
   为什么低：还是访谈，"表演"问题。

→ 我的推荐：A
回 A/B/C。
```
验证方法展开读 references/user-research.md「验证：场景模拟」。

## 收尾（完成度 ≥9/10）
按 references/user-research.md「输出物模板」把共创会洞察 + 场景验证 + 需求清单（真/假标注）写入 plan 文件「流产出」节。
```
✅ 用户研究完成度：9/10
【下一步 — 3 选项】
★ A. 把验证过的需求转成 PEA 评审 9/10 → 继续：体验设计流
  B. 进技术路线（看怎么实现）7/10 → 继续：技术路线流
  C. 整理用户研究报告 8/10
→ 我的推荐：A
```
