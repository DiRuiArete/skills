# 挖用户真实需求：少问，多看，多共创

> "你问一个人想要什么，他会说想要一匹更快的马"——亨利·福特。乔布斯也讲过同样的话。**用户调研不能靠传统的一对一问卷**。本文给你两套替代方法 + 验证机制。

## 核心原则

挖需求最大的敌人是 **"表演"**——用户面对你时会无意识地展示自己"懂行"、"高级"。这不是不真诚，是人性。

替代方案：

```
传统调研（少做）          ❌ 表演 + PM 引导
       ↓
共创会（多做）            ✅ 戒备心放下，需求自然涌现
+
回到现场观察（多做）       ✅ 用户没在被观察，行为最真实
+
场景模拟验证              ✅ 用真实场景判断真假需求
```

## 方法 1：少做一对一访谈，多做多人共创

### 为什么共创比访谈好

| 一对一访谈 | 多人共创 |
|---|---|
| 用户表演给 PM 看 | 用户彼此讨论，戒备心降低 |
| PM 在引导（一来一回） | 相似需求自发聚合、深化 |
| 错过你没想到的需求 | 突破 PM 的盲区 |

### 经典案例：儿童版"理想同学"共创会

- 初期意见五花八门：管控孩子 / 让孩子开心 / 教育功能
- 讨论一段时间后，自然向两个方向聚拢：管控 vs 开心
- 理想选择：**让孩子开心**（孩子才是真用户，不是家长）
- 结果：上线后用户反馈孩子特别喜欢，一上车就玩

### 共创会的 4 条原则

#### 1. 分小组，最后汇总
- 不要 20 个人同一组——会出现意见领袖压制其他人
- 拆成 3-4 组分头讨论，最后碰撞
- 每组配 1 个团队的人记录、活跃气氛（不主导）

#### 2. 问场景，不问需求
- ❌ "你希望车载助手的儿童版加什么功能？"
- ✅ "平时开车带娃，孩子跟车里的语音助手都发生过哪些互动？"

**为什么**：让用户描述场景比让用户提需求更真实。PM 从场景里挖洞察，比让用户给方案靠谱。

#### 3. 问感性期待，不问具体方案
- ❌ "我们打算做成语接龙，你觉得有用吗？"（无论怎么答，用户都被框死在你的方案里）
- ✅ "假如车里多了一位陪孩子的伙伴，你期待 Ta 是谁——爱学习的哥哥、能唠嗑的朋友，还是一只萌宠？"

**为什么**：感性期待激发底层需求。有用户会答"小时候盼着身边有个真正懂自己的人，如今希望孩子能拥有"——这类回答里藏着产品方向。

#### 4. 不要现场出结论
- 共创会要的是**用户尽情表达**
- 收束与取舍留给产品团队会后完成——别把选择压给用户
- 现场就收敛，会让部分用户觉得"我被否定了"

## 方法 2：去看，不要去问

### 现场观察的两种类型

#### 类型 A：去用户家里待一天
- 不带任何目的
- 只是观察用户的真实生活和用车场景
- 自己从中总结提炼高频需求

#### 类型 B：去销售一线（4S 店）
- 不是为了买车，不是为了修车
- 看销售在怎么卖车——讲哪些话用户买账
- 看用户为什么来——开什么车来的、几个人来的、说什么话、觉得什么好/不好

**关键洞察**：用户**准备掏真金白银的时候**没有戒备心，自然流露的需求最有价值。

### 观察的注意事项

**误区**：用户过去用得少 ≠ 没需求。

经典案例：车内后排屏幕。
- 现象：用户使用频率一直很低
- 错误结论："家庭用户不喜欢后排屏幕"
- 真相：过去屏幕体验差、内容差
- 验证：理想做后排屏幕时**对标 iPad**——流畅度和内容跟家里平板一样
- 结果：用户自然就用起来了

**底层逻辑**：需求和供给是双向决定的。**优质的供给本身是激发需求的必要条件**。低使用率可能是供给质量太差，不是需求不存在。

## 验证：场景模拟

收集完需求只是"假设"，要验证真假——企业资源有限，验证有效的才能产品化。

### 唯一的验证方法：回到具体场景

> 不要凭空争论"X 需求存不存在"——脱离场景没答案。

经典案例：车里放冰箱有没有需求？

脱离场景：永远讨论不出结论。

放回场景：
- 大热天父母接孩子放学，车里有冰饮料/水果——孩子开心，父母更开心 ✓
- 全家露营，随时有冰可乐 ✓
- 父母 30-40 岁开始有糖尿病，冰箱保存胰岛素针 ✓（**超级需求**）

→ 强需求。

### 关于位置：冰箱不能放后座/后备箱

放在后座/后备箱不是正常使用场景——像家里一样，**冰箱要放在客厅**。所以理想把冰箱放在车内最容易拿的位置。

**给你的提示**：场景验证不只看"要不要做"，还看"放在哪里 / 怎么呈现"。

### 验证靠谁

找团队里**生活经验丰富**的成员去想象和模拟用户场景。有体验、能共情真实用户，验证不难——难的是**做得彻底**。

### 经典执行案例：双扶手事件

CEO 自己感觉到二排扶手会撞肋骨——但没拍板，**花了一个周末接送十几个朋友亲测**——确认是高频问题，才决定改成单排扶手。

> **场景验证 = 模拟 + 执行彻底**。这是避免拍脑袋的最大武器。

## Playbook：用户研究 5 步

### Step 1: 决定方法
- 复杂高频功能 → 共创会
- 想观察真实使用 → 去用户家 / 4S 店
- 想验证假设需求 → 场景模拟

### Step 2: 共创会执行
4 原则：分小组 / 问场景 / 问感性期待 / 不现场出结论。

### Step 3: 现场观察
不带目的，只观察。把"我们用户"和"我们看到的用户"做对照。

### Step 4: 场景验证
每个候选需求放回 3 个真实场景，模拟用户的体验。

### Step 5: 彻底执行
不要满足于"应该是这样"——真去找用户验证。一个周末换来一个正确决策值不值？值。

## Checklist

- [ ] 我们做的是共创不是访谈（或者并行做）
- [ ] 共创会分了小组、问的是场景而非需求
- [ ] 我有去过用户的真实使用现场（家里 / 销售一线）
- [ ] 我把每个需求都放回 3 个真实场景验证过
- [ ] 没把"用户用得少 = 不需要"当结论（先排除"供给质量差"的可能）
- [ ] 关键决策**亲身验证过**（像 CEO 接送朋友亲测扶手）

## 常见误区

| 误区 | 真相 |
|---|---|
| "用户调研做得越多越懂用户" | 错——表演越多。少调研多观察 |
| "用户说想要 X，那就是需求" | 用户说的是方案，要追问场景和底层任务 |
| "用户用得少证明没需求" | 可能是供给太差。先排除供给原因 |
| "在共创会上让用户做决策" | 共创会只是表达，决策是产品团队的工作 |
| "想象一下应该差不多" | 不彻底。亲自去现场验证一个周末好过想一年 |
