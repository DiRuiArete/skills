# 团队标准：把不同背景的人捏成一个团队

> 团队从外面招进来的人都被原公司"刻画"过——通用、阿里、华为、宜家各有方法论。怎么让这批背景各异的人真正协同起来？三个动作：**统一度量衡 / 嵌入流程 / 培养成年人**。

## 核心原则

团队标准的目标 = 让一群有不同背景的成年人，在做产品时**步调一致**。

经典反例：开会时一个问题讨论来讨论去，每人都觉得自己对——追溯原因发现，**连某个词的定义都不一样**。每个人努力，但都在不同方向使劲，团队是撕扯的，不是前进的。

## 动作 1：统一度量衡

> 在统一思想之前，先在语言和度量衡上统一。

### 工具一：产品四步法

讨论任何产品问题前，先按这四步走（不许"以前怎么干的"）：

| 步骤 | 内容 |
|---|---|
| 1. 问用户 | 用户是谁？真实需求是什么？ |
| 2. 问自己 | 作为企业，我们的诉求是什么？ |
| 3. 设定目标 | 目标 + 符合目标的具体规划 |
| 4. 预估结果 | 目标如何衡量？根据结果倒推动作 |

四步看起来简单，关键是**所有人都按这四步说话**——避免"我们一汽是这样的"、"我们通用是那样的"鄙视链。

### 工具二：通用框架统一

理想用的：
- **OKR** —— 目标管理
- **TBP** —— 丰田工作法（解决问题）
- **IPD** —— 集成产品开发流程

具体选哪套不重要，重要的是**全公司只用一套**。

### 工具的价值观（重要提醒）

工具不是中立的，**工具有自己的价值观**。选工具要看跟你团队基因匹配不匹配。

**理想的选择案例**：选问题解决工具时，**丰田工作法 vs 六西格玛**——
- 丰田：让每个团队成员发挥价值，持续成长、持续迭代
- 六西格玛：追求精准，零缺陷

理想选丰田。原因：汽车不可能零缺陷，长期在零缺陷价值观下工作，**人会下意识掩盖错误**——这跟"做正确的事"的文化冲突。

> **给你的提醒**：很多公司引入了"很好的工具"但坚持不下来——根本原因是工具价值观和团队文化打架。先看价值观匹配，再看工具好坏。

### 共创选工具（不要老板拍板）

让核心团队各自调研工具、列出优劣、最后投票。共创过程本身在巩固团队文化。

## 动作 2：嵌入流程，僵化执行

### 关键洞察：培训没用，要嵌入工作流

很多公司喜欢搞培训——讲一讲、培一培。**没用**。培训完一周就忘。

正确做法：把标准**嵌入到必经流程里**——团队不按标准做就走不下去。

### 经典案例：PEA（产品体验评审）

理想的做法：把四步法固化成 **PEA（Product Experience Assessment）评审**——任何产品动作都必须从这道评审出发。

僵化到什么程度？

> 哪怕你只是想给高管拍一组形象照、调整车机地图上的指北针样式——**也要走 PEA 评审**。

### 为什么必须僵化？

"聪明人"想跳过流程是常态——因为他觉得自己经验丰富。一旦允许跳过，**所有人都会觉得自己是聪明人**——流程立刻形同虚设。

僵化执行不是僵化思考，是**让所有人在同一起跑线上思考**。

### 给你的方法

1. 找出团队最重要的 1-2 个动作（产品决策？技术评审？发布判断？）
2. 把这个动作配套的标准做成**强制流程**（评审会、模板、签字）
3. **没有例外**——不管职级多高、经验多老
4. 流程要能"挡掉" 拍脑袋决策——让人没办法绕开

## 动作 3：培养成年人

### 关键判断：先是成年人，再是专业人才

理想的人才标准：

> **专业能力很好的"巨婴"打不出好产品。** 一个能独立面对问题、能协作解决问题、能不断成长的成年人——是产品经理的底线。

### 为什么是"成年人"？

成年人的特征：
- 能定义自己的目标和问题（不需要全程被指挥）
- 能跟人协作（不会成为团队冲突中心）
- 能不断迭代（不会卡在某个状态自我感觉良好）

理想用《**高效能人士的七个习惯**》作为框架：

| 习惯 | 在干嘛 |
|---|---|
| 主动积极 / 以终为始 / 要事第一 | 处理好和**自己**的关系 |
| 双赢思维 / 知彼解己 / 统合综效 / 不断更新 | 处理好和**别人**的关系 |

### 培养落地：纳入考核 + 强制案例

只培训没用——要考核。

**关键设计**：
1. 每人除了业绩评价，还做"七个习惯"的**自评 + 360 环评**
2. **硬约束：不能只打分，必须举真实案例**——"打分会考虑私人关系，案例只能实事求是"
3. 中层管理者必须做新员工培训讲师，讲自己对七个习惯的理解

### CEO 的自查样板

李想用"要事第一"自查的例子：他追问自己，CEO 的第一用户究竟是谁——答案是员工，用户是被员工服务到的。据此他把八成以上的时间投在与员工相关的工作上，极少跑外部发布会、也不下一线卖车。

**给你的方法**：管理者每条习惯都要能配真实案例自证。讲不出案例的，没做到。

## Playbook：建立团队标准 5 步

### Step 1: 选 1 个统一度量衡的工具
从产品四步法 / OKR / TBP / IPD 选一个，作为公司的**第一标准语言**。

### Step 2: 把核心动作做成强制流程
找出最重要的产品动作（评审、决策、发布），做成 PEA 一类的强制流程。**没有例外**。

### Step 3: 选人时看"成年人"
专业能力是底线，但能不能独立、能不能协作、能不能成长是真分水岭。

### Step 4: 七个习惯纳入考核
自评 + 360 环评 + **强制举真实案例**。

### Step 5: 管理者必须做培训讲师
中层是上下承接的关键。让他们讲，他们才会真的内化。

## Checklist

- [ ] 我们有 1 套大家都用的"产品讨论语言"（四步法 / OKR / TBP）
- [ ] 我们至少有 1 个**僵化执行**的强制流程，不允许任何人跳过
- [ ] 我们选工具时考虑过"工具的价值观跟团队文化匹配吗"
- [ ] 我们的人才标准包含"成年人"维度，不只是专业能力
- [ ] 我们的考核要求**列真实案例**，不只是打分
- [ ] 中层管理者会讲我们的工作方法（不是只听不讲）

## 常见误区

| 误区 | 真相 |
|---|---|
| "先统一思想再说" | 反——思想最难统一；先统一语言、度量衡 |
| "招最厉害的专业人才" | 巨婴专家比成年通才更难合作 |
| "聪明人可以跳过流程" | 一开口子就全员跳过——必须僵化 |
| "培训就能培养能力" | 培训记不住——要嵌入流程让人不得不练 |
| "工具就是工具，无所谓价值观" | 反——丰田 vs 六西格玛是价值观选择 |
| "考核打分就够了" | 打分会被人情污染——必须要求列案例 |
