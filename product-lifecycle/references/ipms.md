# 流程：把游击队升级为集团军

> 0→1 时期产品少团队小，"游击队"快速灵活就够了。**1→10 阶段产品一多、收入上千亿，流程问题成为持续打造爆品的最大障碍**——必须从"小区道路"升级到"高速公路"。

## 核心原则

流程 = 路。

```
游击队（0→1）          集团军（1→10）
─────────              ─────────
小区道路               高速公路
快速灵活               规矩多但效率高
个人能力               系统能力
```

**关键洞察**：高速公路规矩最多，但**运输效率最高、事故率最低**。

### 真实代价：理想 ONE 销量崩盘事件

理想 L9 上市后，理想 ONE 销量迅速下滑（出乎团队意料——以为 10 万元价差不会互相影响）+ 引起老车主抗议。

根本原因：**没有"老产品退市操盘"流程**。新产品上市时，老产品该怎么处理 — 团队从来没准备过方案。

→ 流程的漏洞，到了规模化阶段就会变成"车毁人亡"。

## 三个核心动作

```
1. 还原用户价值流
2. 修好高速公路（区分路和车）
3. 关键节点对齐互锁
```

## 动作 1：还原用户价值流

### 关键洞察

很多团队梳理流程时**从内部员工视角出发**——结果只能想到自己部门的事，**不同部门衔接处全是断点**。

**正确做法**：从用户视角倒推，模拟用户真实使用产品的全流程，**所有内部流程一一对应到用户价值流上**。

### 案例：IPMS 流程的用户价值流

IPMS = Integrated Product Marketing & Sales（产品营销与销售流程）

用户价值流（用户的真实路径）：

```
知道品牌 → 了解产品 → 产生兴趣 → 完成试驾 →
产生购买意向 → 下单 → 交付 → 使用 + 后续服务
```

每个接触点 → 反推内部需要哪些动作、哪些部门协作。

### 案例：试驾响应时间

用户预约试驾后的第一诉求：**多久响应**——2 分钟？10 分钟？半天？

- 内部员工视角："我有 X 人就干 X 活" → 算出一个流程时间
- 用户价值视角：**超过半天没人响应，用户兴趣就没了**

→ 流程时间不是从内部产能算，是从**用户接受的最大等待时间**反推。

### 给你的方法

1. 画出用户跟产品的所有接触点（从知道到使用全周期）
2. 每个接触点问："用户的第一诉求是什么？"
3. 把这些诉求作为流程目标
4. 反推内部需要哪些部门怎么协作
5. **不在用户价值流上的流程 → 删掉**（任何团队跑一段时间都会积累冗余流程）

## 动作 2：修好高速公路（区分路和车）

### 路 = 流程

理想用的两条主路：
- **IPMS** = Integrated Product Marketing & Sales（产品营销 + 销售流程）
- **IPD** = Integrated Product Development（集成产品开发流程）

### 车 = 支撑流程关键节点的专业模型

举例：IPMS 中"零售管理"是关键节点——怎么确保零售目标达成？

→ 销售漏斗模型：传播 → 线索 → 试驾 → 成交。

漏斗模型 = "车"。流程节点（零售管理）= "路"上的一个点。

### 完整的体系：路 + 车

一个好的流程不仅是连接各部门工作，**还要规划从生产到用户价值实现的全路径**——理想称为"价值创造、价值传递、价值交付"。

| 角色 | 干什么 |
|---|---|
| 各部门高级业务专家 | 造"车"（专业模型） |
| 一线员工 | 开"车"（执行模型） |

### 为什么必须区分路和车

→ **归因能让定位更准确**：
- 路有问题 → 修路
- 车有问题 → 修车
- 不能把问题都甩到开车人身上

### 给你的方法

1. 定义你的"路"（公司主流程：研发流程、营销流程、销售流程）
2. 找出每条路上的关键节点
3. 为每个关键节点定义"车"（支撑模型 / 工具）
4. 高级专家造车，一线员工开车
5. 出问题先看是路问题还是车问题，不是开车人问题

## 动作 3：关键节点对齐互锁

### 为什么强调互锁

产品一多，部门目标天然不一致：
- 产品团队：关注 2-3 年后的新产品
- 品牌团队：关注今年的新发布
- 销售团队：关注正在销售的产品销量

→ **三不管地带**就出现了（比如老产品退市没人管）。

### 关键 1：定义主流程 + 支线流程

错误做法：每个事业部各自一套流程，平行存在 → 像高架桥一样看起来重叠但没接口。

正确做法：
- 公司层面定义**主流程**
- 各部门支线流程**搭建在主流程上**
- 接口处做关键节点互锁

#### 例子：营销 + 销售 必须在产品立项阶段就介入

很多公司错误做法：营销/销售到产品**临上市才介入**——已经太晚。

理想做法：从产品立项阶段，营销/销售团队就**参与全生命周期管理**——直到产品退市操盘也是他们的责任。

### 关键 2：重量级 PDT 团队做拉通

很多公司有"产品经理"或"项目经理"——但常变成**催进度 + 传话的人**，不能真正为产品负责。

**为什么**：不是授权不够——是**没给到工具和专业支持**。产品经理不懂财务/不懂研发 = 只能传话。

#### PDT 团队组成

PDT = Product Development Team（华为方法论）。组成必须是**重量级团队，不是个人**：
- 研发
- 市场
- 财务
- 采购
- 制造
- ……各业务线专业人士

**他们共同为产品成功负责**——彼此的建议有说服力 + 权威性。

### 从 OKR 到契约制：信任 → 互锁

理想以前用 OKR：信任制——大家相互信任、各自努力。

升级到流程后：**契约制**——团队和团队之间的契约，每个人和团队之间的契约。

效果：
- 制定目标时**真正相互挑战**
- 做事时**毫无保留密切协作**
- 目标达成率 + 工作质量根本性提升

## 学习对象：华为

理想全面学华为——**复杂软硬件研发 + 千亿规模业务 + 多个爆款同时操盘** 中国最有经验的公司。

### 关键书单（最少读三本）

| 必读 | 关于 |
|---|---|
| 《华为基本法》 | 文化与底层逻辑 |
| 《DSTE 实战体系》 | 战略管理 |
| 《从偶然到必然》 | 研发投资与管理 |

各业务领域延伸阅读：研发、供应、财经、变革与 IT、人才组织文化（具体书单见李想原课程）。

## Playbook：建流程 4 步

### Step 1: 还原用户价值流
画出用户全周期接触点 → 删掉冗余流程。

### Step 2: 定义路
公司主流程（IPMS / IPD）— 不是各部门各搞各的。

### Step 3: 造车
为每个关键节点造支撑模型（销售漏斗等专业工具）。

### Step 4: 互锁
- 主流程 + 支线流程层级关系明确
- 在关键节点做契约式互锁
- 组建重量级 PDT 团队拉通

## Checklist

- [ ] 我们的所有流程都对应到用户价值流的某一段
- [ ] 我们删掉了团队累积的冗余流程
- [ ] 我们定义了公司主流程，不是各部门平行流程
- [ ] 每个关键节点都有专业模型（"车"）支撑
- [ ] 营销 + 销售在产品**立项阶段就介入**，不是临上市
- [ ] 我们有重量级 PDT 团队，不是单兵产品经理
- [ ] 出问题时区分**路 / 车 / 开车人**，不是甩锅给执行者

## 常见误区

| 误区 | 真相 |
|---|---|
| "流程降低效率" | 反——高速公路效率高于小区路 |
| "OKR 信任制就够了" | 1→10 必须升级到契约制（互锁） |
| "产品经理一个人就能拉通" | 错——必须是重量级 PDT 团队 |
| "营销销售临上市才介入" | 错——立项阶段就介入，全周期负责 |
| "出问题就找执行者" | 错——先区分路 / 车 / 人 |
| "学华为太复杂，我们小" | 学习的是**思维方式**，不是抄具体流程 |
