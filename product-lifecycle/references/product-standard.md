# 产品标准：定义什么样的产品才算好

> 光有定位还不能动手做——"做成什么样才算好的家庭车？"团队没共识就会撕扯。这一文给你一套通用的产品标准框架：**安全感 / 价值感 / 向往感**。

## 核心原则

产品标准 = 产品定位的进一步拆解 + 塑造产品力的硬维度。

这套标准的三维度对绝大多数"既有功能性、又体现生活方式"的产品（汽车、手机、家电、家居、消费电子）通用：

| 维度 | 决定 | 缺失会怎样 |
|---|---|---|
| **安全感** | 用户会不会被劝退 | 无 → 木桶最短板，基础销量都没有 |
| **价值感** | 用户会不会买 | 无 → 同价位被竞品轻易压死 |
| **向往感** | 用户会不会形成口碑 | 无 → 卖出去，但没复购、没传播 |

三个维度按顺序：**先把劝退点除掉，再做价值感，最后做向往感**。

---

## 维度 1：安全感（底线）

### 关键洞察：先看致命缺点，再看亮点

做产品的常见错误：先想"亮点"。

**正确做法**：先扫描 "致命缺点"——任何会让用户直接劝退的硬伤。这个硬伤通常和**安全感**相关（物理安全、数据安全、心理安全、信任安全）。

### 提升安全感：突破行业惯性

汽车行业人会觉得"安全已经卷到极致了"——但其实**惯性里全是空间**。

经典案例（25% 偏置碰撞）：
- 行业惯性：主驾比副驾的安全结构强（成本省、减重、工程容易）
- 用户视角：**最常坐副驾的是配偶**——为什么副驾要比主驾安全等级低？
- 理想选择：主副驾同等安全。多花的成本，写进产品价值里。

### 给你的方法

**视角切换法**：
1. 列出所有"行业默认妥协"（"行业一直这么做的"、"成本考虑"、"技术限制"）
2. 切换到用户视角——他知道这些约束吗？他在乎吗？
3. 找到"行业觉得合理 / 用户不会接受"的妥协点 → 这就是安全感的提升空间

**给你的提醒**：
> "安全感"不只是物理安全。对软件产品 = 数据隐私、系统稳定、错误恢复；对金融产品 = 资金安全、风控；对工具 = 不会丢失用户的工作。**用户最怕失去的东西**就是安全感。

## 维度 2：价值感（竞争力）

### 定义

价值感 = 同样的钱，用户买到的功能和体验，**对他自己**是不是最好的。

不是堆功能、不是刷参数、不是做厂商的存在感。

### 反例：东施效颦

L9 的 4D 震动座椅 + 二排大屏 + 4D 影院体验：用户向往的是"在车里看震撼电影"。

某竞品看到了，**直接搬功能**：装了 4D 震动座椅。但他们没有大屏、没有空间、座椅厚度不支持——为了塞进 4D，**砍掉了座椅通风**。

结果：表面功能学到了，对用户毫无价值，还失去了实用的通风。**失败的产品**。

### 价值感的判断准则：完整性 vs 拼凑

| 判断 | 高价值感 | 低价值感（拼凑） |
|---|---|---|
| 功能间关系 | 互相支撑成完整体验 | 互相打架，砍东补西 |
| 取舍逻辑 | 围绕一个用户群做透 | 想讨好所有人 |
| 看待功能 | 能不能形成场景闭环 | 能不能加在功能列表上 |

### 给你的方法

1. 锁定核心用户群（来自 `positioning.md`）
2. 列出他在你产品上的**完整使用场景**（不是单点功能）
3. 每个场景下，问："这套功能组合在他的体验里是不是闭环？"
4. **不闭环的功能宁可砍掉**——半截功能 = 价值感损失

### 价值感的反馈：NPS

**净推荐值（Net Promoter Score）** 是验证价值感的最主要数据。NPS 高 = 用户真的觉得"花这个钱值"，会主动推荐给同类用户。

> NPS 的具体用法在复盘方法里详细讲（见 `references/retro.md`）。

## 维度 3：向往感（口碑）

### 定义

向往感 = 用户**渴望拥有**的场景。让产品**唤起**用户心里向往的画面。

### 关键洞察：不是堆功能或堆成本

很多人一看到"向往感"就想：是不是要加奢华材质？加高级科技？要花大钱？

**反——向往感的核心是对用户场景的洞察**，便宜也能做出向往感。

### 经典案例 1：冰箱、彩电、大沙发

理想为什么在车里加冰箱、二排大屏、大沙发座椅？

**底层洞察**：家庭用户对"自家客厅"的向往。冰箱 + 彩电 + 大沙发 = 客厅的标配。一上车就唤起"全家在客厅其乐融融"的画面。

不是堆功能，是**嫁接用户已有的向往画面**到产品上。

### 经典案例 2：对外放电（便宜的向往感）

家庭用户向往露营。露营要野炊、看电影。但是车上加个"对外放电"功能——基本不动车身结构、几乎不花成本——用户立刻脑补：

> "电磁炉、电热水壶、咖啡机、空气炸锅、投影仪……我可以在户外搞个家！"

**便宜的向往感比贵的向往感更高级**——因为它来自洞察，不是来自钱。

### 给你的方法

1. 列出目标用户**最向往的 3-5 个场景**（露营、客厅、咖啡馆、深夜独处、家人聚餐...）
2. 每个场景拆解：用户脑海里这个画面有什么核心元素？
3. 把核心元素**嫁接到你的产品里**——可以是大功能，也可以是不起眼的小功能

## Playbook：建立产品标准 4 步

### Step 1: 确定三维度的具体内容

每个维度对你的产品意味着什么？写成可验收的描述：
- 安全感：[具体劝退场景列表 + 你的解法]
- 价值感：[完整体验场景 + 必要功能闭环]
- 向往感：[用户向往画面 + 嫁接到产品的方式]

### Step 2: 用安全感做防守

发布前，让团队（不只是 PM、还要拉销售/客服/质量）扫一遍——还有哪个劝退点没处理？逐个解决。

### Step 3: 用价值感做选择

每个功能问一遍："砍掉这个功能，体验闭环还成立吗？" 不闭环的功能补完整或砍掉，**绝不留半截**。

### Step 4: 用向往感做加分

找 3 个不起眼的小功能，让它们在用户场景里"唤起向往画面"。这是性价比最高的产品力来源。

## Checklist

- [ ] 我能列出 5+ 个用户**劝退点**，每个都有解法
- [ ] 我们的功能组合在**目标用户的场景**里是闭环的，不是功能列表的拼凑
- [ ] 我能找出 3+ 个 "不起眼但能唤起用户向往" 的小功能
- [ ] 团队在做功能取舍时，能用三维度作为统一语言（不是吵"亮点 vs 实用"）
- [ ] 我们有 NPS 或类似的价值感反馈机制

## 常见误区

| 误区 | 真相 |
|---|---|
| "先想亮点再说" | 反——先扫劝退点。木桶最短板没解决，亮点没用 |
| "功能越多越值" | 反——拼凑功能损害价值感；闭环的少功能 > 半截的多功能 |
| "向往感要花大钱" | 反——向往感的核心是洞察，"对外放电"比 4D 座椅更高级 |
| "竞品有 X 我们也得有 X" | 东施效颦——抄功能不抄场景闭环 = 失败的产品 |
| "标准就是 PRD 列要求" | PRD 是结果；标准是团队在做取舍时共享的判断框架 |
