# 体验设计：高频 × 机会 × 务实

> 设计体验最难的不是想 idea，是**取舍**——空间/资源/精力都有限，每加一个功能就得砍一个。本文给你三条筛选准则，避免拍脑袋。

## 核心原则

体验设计 = **三条筛子叠加**：

```
       高频 ──────┐
                  ├── 值得做的体验
       机会 ──────┤
                  │
   务实（不带麻烦）─┘
```

少一条都做不出超越用户预期的体验。

## 准则 1：不分大众小众，只看高频

### 为什么"大众/小众"是过时的判断维度

经典反例：短视频出来之前，"看几十秒短视频"是大众还是小众需求？答：**小众**。但碎片时间几乎人人可看 → 一旦做出来就变成超高频。

**大众/小众的判断会错过"低门槛 + 超高频"的金矿**。

### 正确判断：使用频率

判断一个功能值不值得做，看的不是"多少人会用"，而是"用上的人会用多频繁"。

**经典案例：电吸门下放到非豪华车**

- 行业惯例：电吸门只在百万豪车上有，被当作豪华标志
- 理想做法：把它做成 L7/L8/L9 标配
- 理由不是"豪华感"，是**关门是高频动作**——每天发生很多次
- 隐藏价值：家庭用户尤其感知——孩子在车里睡觉，关门不会吵醒

### 给你的方法

1. 列出目标用户在你的产品上的所有交互动作
2. 标注每个动作的**频率**（每天/每周/每月/极少）
3. 优先把资源砸在每天发生的动作上
4. 砍掉资源在"听起来酷但极少用"的极端场景功能上

## 准则 2：权衡机会——找竞品没做好的地方

### 关键洞察：明牌竞争里没有秘密

你能看到的高频需求，竞品也能看到。**所以高频还不够，要叠加"机会"维度**。

**机会 = 竞品已经做了，但没做透；或现有方案还有完善空间**。

### 思路 1：原子级对标

理想内部说法："细分到原子级的配置"。

座椅加热为例：
- 现状：很多车都做了座椅加热——笼统看，没差别
- 深入对比：竞品只做底部 + 背部加热，**侧面冰凉**
- 理想做法：加上**侧翼加热** → 才算有竞争力

**给你的方法**：把每个功能拆到原子级，每条原子项跟竞品逐一比对。

### 思路 2：把目标用户分得更细致

理想从"家庭用户"细分到"驾驶员 + 副驾女主人 + 后排老人 + 后排孩子"——每个角色有不同需求。

**经典案例：6 音区语音识别**
- 行业惯例：语音助手只服务前排主驾
- 理想做法：6 个音区独立识别 → 后排孩子叫"理想同学"调空调，"你好，二排"精准响应
- 价值：每个家庭成员都有"主人感"

### 给你的方法

1. 把目标用户细分到具体角色 / 场景 / 时刻
2. 对每个细分单元，问："现有方案有没有为他做过专门设计？"
3. 没做过的就是机会

## 准则 3：务实——不要带来更多麻烦

### 关键反例：全景天幕

近几年新车流行一整块玻璃车顶——视觉通透、夜里看星星。

**问题**：大太阳底下晒到要在车里打伞。用户调侃视频满网都是。

理想的选择：**放弃全景天幕，用普通物理遮阳帘**——
- 太阳大：拉上遮阳帘
- 看星星：打开
- 防晒和视野两不耽误

### 抵御"概念诱惑"

新技术 / 新概念容易让用户兴奋下单，但日常使用中会暴露麻烦。耐用消费品尤其要警惕——用户会用脚投票，下次不买你了。

### 给你的方法

每加一个新体验，问三个问题：
1. 加了这个体验，有没有同步加新麻烦？（晒、噪音、维护、学习成本……）
2. 麻烦的影响大于体验提升吗？
3. 有没有更朴素但综合体验更好的方案？

## PEA 流程：把以上准则落地到团队

PEA = Product Experience Assessment（产品体验评审）。理想所有产品动作的起点。

### 僵化执行

- 哪怕调地图指北针样式 / 给高管拍形象照——都要走 PEA
- 没有例外，不允许跳过

### PEA 模板（六维度）

| 维度 | 内容 |
|---|---|
| 1. 解决什么问题 | 痛点描述 + 来自哪个用户群 |
| 2. 目标 | 量化目标 + 时间限制 + 衡量方式 |
| 3. 产品方案 | 功能要点 + 数据支撑 + 体验细节 |
| 4. 关键技术 | 实现方案 + 技术路径 |
| 5. 资源评估 | 研发资源 + 上下游协同 |
| 6. 效果评估 | 预期效果 + 发布后回填实际效果 |

完整模板：`templates/pea-template.md`

### 评审记录

PEA 评审产出：通过 / 通过 N 次 / 修改记录

## Playbook：体验设计 5 步

### Step 1: 列高频动作清单
基于目标用户的真实使用场景，列出他每天/每周做的事。

### Step 2: 三筛选
对每个候选功能：高频 ✓ → 机会 ✓ → 务实 ✓ 三个 yes 才进开发。

### Step 3: 原子级对标
进开发的功能逐个跟竞品做原子级比对，找差异化点。

### Step 4: 角色细分
把目标用户拆成 3-5 个具体角色，每个功能问"为这个角色做了什么专门设计"。

### Step 5: PEA 评审
所有动作进 PEA，团队对齐六个维度后才执行。

## Checklist

- [ ] 这个功能是用户**每天/每周**会用的（不是听起来酷的极端场景）
- [ ] 这个功能在竞品已做的基础上**有原子级差异化**
- [ ] 加了这个体验**没带来新麻烦**（或麻烦远小于提升）
- [ ] 这个功能为**至少 1 个具体的用户角色**做过专门设计
- [ ] 这个功能进了 PEA 评审，6 个维度都填清楚了

## 常见误区

| 误区 | 真相 |
|---|---|
| "这是小众需求，不做" | 小众的高频功能比大众的低频功能更有价值 |
| "竞品都没做的我们也不做" | 竞品做没做不是判断标准——高频 × 机会 × 务实才是 |
| "新技术更高级" | 新技术 ≠ 更好体验。带麻烦的新技术是负分 |
| "PEA 流程太繁琐，重要的事可以跳过" | 一开口子就全员跳过——必须僵化 |
| "用户调研说他们想要 X" | 用户表达的是方案，要追问场景和底层任务（→ user-research.md）|

## 输出物模板

```
功能名称：[XX]

【高频判断】
- 使用频率：[每天/每周/每月]
- 高频证据：[具体场景描述]

【机会判断】
- 竞品现状（原子级）：[A 做了 X，B 做了 Y]
- 我们的差异化点：[XX]
- 服务的细分角色：[谁]

【务实判断】
- 这个体验带来什么麻烦？[列出]
- 麻烦小于提升吗？[是/否 + 论证]

【PEA 评审】
（按六维度填，进入评审）
```
